# ADR-0001: Надёжная запись и повторная обработка

Статус: принято для прототипа v0.1.0.

## Контекст

В ingest нельзя подтвердить приём, пока данные не зафиксированы в PostgreSQL. Отдельная очередь с двухфазным подтверждением усложнила бы отказоустойчивость для демонстрационного масштаба.

## Решение

В одной транзакции сохраняются ingest_events и outbox. HTTP 200 только после commit. Worker забирает outbox (SKIP LOCKED на PostgreSQL), создаёт alerts/incidents/timeline и помечает задачу обработанной в той же транзакции. Unique constraints контролируют повторные эффекты: (key_id,event_id), fingerprint, (incident_id,level).

Состояние ACK меняется условным UPDATE. При ошибке/rollback worker выполняет обработку заново. Изменение документации должно прямо исключать обещания exactly-once delivery.

## Последствия

Плюс: меньше инфраструктуры и простой replay после crash. Минусы: PostgreSQL — bottleneck; длительная транзакция worker может замедлить запись; для высоких объёмов нужен специализированный broker или более мелкие транзакции. Перед масштабированием требуется fault injection и load test.
