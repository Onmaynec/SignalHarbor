# SignalHarbor v0.3.0 — Detection & Observability

Обновление механизма обнаружения алертов, очереди событий и встроенной диагностики.

## Обработка событий
- Окна count_error/error_rate для допустимых задержанных событий рассчитываются по event-time watermark группы. Например, пачка событий с задержкой 90 секунд может сработать в правиле с окном 30 секунд.
- Для событий с timestamp в будущем outbox-задача остаётся pending до наступления event-time; преждевременное выполнение не приводит к пропуску алерта.
- При создании alert по fingerprint применяется транзакционный advisory lock PostgreSQL. Уникальное ограничение в БД сохраняется.
- В timeline первого alert_fired фиксируется detectionLagMs относительно received_at события.

## Диагностика
- Расширен GET /api/v1/ops: backlog, возраст старейшей задачи, число обработанных outbox за час, число полученных/late событий, оценка p95 обнаружения и размер её выборки.
- Новая вкладка «Диагностика» в интерфейсе администратора.
- SSE повторно валидирует сессию и текущую команду пользователя при каждом опросе; добавлены тесты cursor/изоляции/отзыва сессии.

## Проверки
- Новый набор интеграционных тестов на event-time, future event, fingerprint группировку, диагностику и SSE.
- GitHub Actions использует PostgreSQL 16, Ruff, pytest, compileall, проверку синтаксиса JS и Docker Compose.

## Обновление с v0.2.0
1. Сделать резервную копию PostgreSQL.
2. Выполнить git pull origin main и docker compose up --build -d.
3. Посмотреть логи API, worker и доступность /health/ready.
4. В интерфейсе администратора открыть «Диагностика» и проверить очередь.

Миграция схемы не требуется: версия БД остаётся v2.

## Известные ограничения
AT-10 (2000 events/min, 30 минут и подтверждённый p95), реальный сетевой SSE reconnect, fault injection при kill worker, 180/365-дневное хранение агрегатов/metadata и общая квота на несколько API-реплик пока не завершены. Значение p95 в панели — ограниченная выборочная оценка, не формальное выполнение SLO.
