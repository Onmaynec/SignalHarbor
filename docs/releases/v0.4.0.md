# SignalHarbor v0.4.0 — Performance & Stability

Релиз оптимизирует обработку массовых событий и делает состояние worker наблюдаемым после перезапуска API.

## Изменения

- Пакетная корреляция: в рамках одного outbox batch правило пересчитывается один раз на fingerprint, а не один раз на event. Загрузка событий, сервисов и правил выполняется группами.
- Для count_error/error_rate два счётчика объединены в один SQL агрегат. Блокировки fingerprint берутся в стабильном порядке.
- Введена настройка WORKER_BATCH_SIZE=250 (1–500) для конфигурации размера транзакционного пакета.
- Версия схемы PostgreSQL повышена с v2 до v3: добавлена таблица worker_status для постоянных heartbeat и счётчиков обработанных задач/ошибок.
- API /api/v1/ops и веб-«Диагностика» различают ready/deferred backlog и показывают активные worker с их последними heartbeat.
- Интеграционные тесты имитируют исключение внутри worker-транзакции и подтверждают rollback/retry, параллельный drain с SKIP LOCKED и корректное число alert/incident.

## Установка поверх v0.3.0

1. Создать бэкап PostgreSQL и проверить возможность восстановления.
2. В папке репозитория: git pull origin main.
3. Выполнить: docker compose up --build -d.
4. Проверить: docker compose ps, docker compose logs migrate worker api.
5. Убедиться, что миграция v3 завершена и в административной «Диагностике» виден heartbeat worker.

Новая настройка необязательна: WORKER_BATCH_SIZE по умолчанию равна 250. Значения ограничиваются интервалом 1–500.

## Проверки и ограничения

Автоматизированные тесты покрывают группировку событий, транзакционный rollback, конкурентный drain и отображение состояния worker. Это не подтверждает p95 при нагрузке 2000 событий/мин в течение 30 минут, не заменяет реальные fault-injection эксперименты с остановкой контейнеров и не закрывает все требования PV-OPS-04.

Остаются открытыми: 180/365-дневный retention, cross-replica rate-limit, испытания network reconnect SSE и эксплуатационная нагрузочная приёмка.
