# SignalHarbor v0.5.0 — Data Lifecycle & Security

Обновление посвящено контролируемому хранению данных, исторической аналитике и защите входа.

## Data Lifecycle

- Транзакционное архивирование raw events старше 30 дней в hourly aggregates по team/service/environment, с отдельными счётчиками общего числа событий, ошибок и late events. Payload, labels и ключи в агрегаты не попадают.
- Переход raw→aggregate и удаление исходных событий выполняются в одной транзакции, с advisory lock для конкурентных worker. Pending outbox защищён от преждевременной очистки.
- Хранение агрегатов ограничено 180 днями. Закрытые инциденты сохраняются 365 дней с момента разрешения; после этого удаляются вместе с зависимыми записями. Незакрытые инциденты не удаляются по времени.
- Очистка работает каждые 60 секунд, ограничена порциями по 10000 raw events и 1000 incidents за цикл.
- Новый эндпоинт GET /api/v1/history?days=30..180 объединяет raw events и hourly aggregates, разделяя команды через RBAC. В административной «Диагностике» появился график за 30 дней.

## Security

- Общее PostgreSQL-ограничение попыток входа: восемь неверных паролей за 15 минут приводят к блокировке аккаунта на 15 минут. Возвращается HTTP 429 и Retry-After.
- Для несуществующих аккаунтов выполняется PBKDF2-проверка фиктивного хеша; сообщения об ошибке учётных данных одинаковые.
- Ответы API и SSE отправляются с Cache-Control: no-store.
- Schema v4 добавляет metric_hours и login_attempts с сохранением старой схемы и данных.

## Обновление с v0.4.0

1. Сделать проверяемый бэкап PostgreSQL.
2. Выполнить git pull origin main.
3. Выполнить docker compose up --build -d.
4. Убедиться, что сервис migrate успешно применил v4, и проверить docker compose logs migrate api worker.
5. Проверить /health/ready и экран «Диагностика».

## Ограничения

Автоматизированные тесты проверяют миграции, разграничение доступа, retention и защиту входа, но не подтверждают 30-минутный SLO-тест 2000 events/min, массовую производительность архивации, fault injection с kill контейнеров или полный E2E пяти ролей. Для публичного доступа всё ещё требуются TLS, MFA и сетевой rate-limit; account lockout может стать причиной временного DoS против известного email. Приёмка PV-OPS-04 пока не завершена.
