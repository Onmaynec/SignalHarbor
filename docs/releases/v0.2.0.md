# SignalHarbor v0.2.0 — Reliability Update

Обновление посвящено сохранности данных и повторяемому восстановлению после ошибок.

## Изменения
- Схема PostgreSQL теперь обновляется по версиям: введён транзакционный runner с блокировкой одновременных миграций.
- Миграция v2 добавляет частичный уникальный индекс активного инцидента и индексы для outbox/escalation.
- Создание инцидента сериализовано по окружению. Параллельные worker повторно используют уже созданный активный incident.
- При конфликтующих legacy-инцидентах миграция не удаляет сведения, а останавливается и требует ручного разбора.
- Retention больше не удаляет событие, если его outbox-задание ещё ожидает обработки.
- Во время очистки удаляются просроченные пользовательские сессии.
- Добавлены 5 тестов на миграции, конкуренцию и retention.

## Проверка
- GitHub Actions: Python lint, PostgreSQL migrations, интеграционные тесты, компиляция Python, проверка JavaScript и Docker Compose.
- 20 автоматизированных тестов пройдены на PostgreSQL 16.

## Обновление с v0.1.0
1. Создать и проверить бэкап PostgreSQL.
2. Проверить отсутствие нескольких активных инцидентов для одной пары service/environment.
3. Запустить docker compose up --build -d. Отдельный сервис migrate применит v2 до запуска API.
4. Проверить docker compose logs migrate api worker и статус API.

## Ограничения
Это промежуточная версия; полной приёмки по PV-OPS-04 нет. Не подтверждены длительный нагрузочный тест и p95 SLO, 180/365-дневный retention и end-to-end сценарии restart/SSE. Открытые Issues остаются актуальными.
